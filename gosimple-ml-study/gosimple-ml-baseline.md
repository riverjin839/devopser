## gosimple ML 도입 검토 - 급등 사건 데이터셋과 규칙 기준선

> **목표** : "차트 통계 확률 접근이면 ML 이 낫지 않나" 에 숫자로 답할 수 있는 성적표 설계

- 출처 : gosimple 레포 설계 문서 `docs/superpowers/specs/2026-10-27-surge-event-baseline-design.md`, 선행 `2026-08-03-signal-scoring-design.md`
- 기준 버전 : gosimple main `6c50611` (2026-10 기준)

---

## 1. 개요

gosimple = 개인용 AI 보조 트레이딩 대시보드. 매매 판단은 규칙·통계 기반, 직접 학습한 ML 모델은 없음.

<!-- diagram: gosimple-ml-01-overview.html -->

질문은 "ML 이 더 낫나" 였지만 지금은 답할 수 없는 상태. 비교할 성적표가 없기 때문. **ML 도입보다 먼저 같은 잣대로 잴 수 있는 사건 표본과 결과 라벨이 필요함.**

## 2. 개념 정리

### 2-1. 현재 방식도 이미 통계 모델임

| 기능 | 방식 | 학습 요소 |
|---|---|---|
| S급 스크리너 | DETECT → CONFIRM → PULLBACK 상태 머신 | 임계값을 과거 데이터로 캘리브레이션 |
| 시장 전환 알람 | 시그널별 적중률 백테스트 | 최소 표본 + 적중률 10%p 이상 개선 시만 임계값 변경 |
| 뉴스 중요도 | 출처·키워드별 중요 비율 | 베이지안 수축(표본 적으면 평균 쪽으로) |
| 모멘텀 점수 | 거래대금·수급·RSI 가중합 | 가중치 수동 |

- 사전학습 모델은 사용 중 = 로컬 LLM(qwen), 임베딩(bge-m3), Claude API
- ML = 규칙과 임계값을 데이터에서 자동으로 찾는 방법. 차이는 정도 문제

### 2-2. ML 이 불리한 조건

| 조건 | gosimple 현실 |
|---|---|
| 라벨 붙은 표본 수 | S급 기준 종목 6개, BUY_SIGNAL 7건(2026-08 기준) |
| 기간 | 일봉 600봉 한계 → 약 2.4년, 시장 국면 1~2개 |
| 데이터 품질 | 과거 시총 근사, 상장폐지 종목 누락 |
| 설명 가능성 | 모든 판정에 hover 근거 표시가 앱 규칙 |

> 주의 : 표본이 적은 상태에서 "S급인가" 를 바로 ML 로 맞히면 우연을 패턴으로 외우는 과적합(overfitting)이 거의 확실함

### 2-3. ML 이 나을 수 있는 자리

- DETECT 후보 중 "진짜 가는 것" 순위 매기기
- 급등 사건은 약 1만 건 안팎 추정 → 단순 모델(로지스틱 회귀, LightGBM)은 학습 가능한 규모
- 단, 실제 건수는 DB 기동 후 확인 필요

### 2-4. 기존 채점(2026-08)으로 부족한 점

| 부족한 점 | 이유 |
|---|---|
| 표본이 DETECT 통과분뿐 | 걸러낸 쪽(음성)이 없으면 DETECT 자체 검증 불가 |
| 코드당 활성 후보 1개 | 같은 종목의 새 급등 누락 |
| 종가 수익률만 | 최대 상승·하락폭, 손절 먼저인지 목표 먼저인지 없음 |
| 시간 분할 없음 | 특정 국면에서만 통한 규칙인지 모름 |
| 기준선 대비 없음 | BUY_SIGNAL 승률이 급등주 전체보다 얼마나 나은지 모름 |
| 리플레이에 현재 시총 | 과거 판정에 미래 정보 누수 소지 |

## 3. 구조 - surge-events-build 잡

<!-- diagram: gosimple-ml-02-pipeline.html -->

### 3-1. 사건 정의

- 사건 = (종목, 거래일) 중 당일 종가 상승률 10% 이상
- DETECT 문턱(15%)보다 낮게 → 15% 문턱 자체도 같은 표본으로 시험
- 코드당 1개 제한 없음. 대신 연속 급등 표시 컬럼
- 유니크 키 = `(code, event_date)`

### 3-2. 입력 지표 - 사건일까지 봉만 사용

| 묶음 | 지표 |
|---|---|
| 당일 | 상승률, 거래대금, 시가 갭, 종가 위치, 윗꼬리 |
| 거래대금 | 20일 평균 대비 배수, 시장 내 대금 순위, 10일 누적대금/시총 |
| 가격 위치 | 60일·252일 고가 대비, 126일 박스 범위 |
| 직전 흐름 | 5·20·60일 수익률, 10일 내 +20% 급등 횟수, 연속 상승일 |
| 규모 | 근사 시총, 시장 구분 |
| 규칙 판정 | DETECT 통과 여부, 실패 사유, 설정 해시 |

**입력 지표는 사건일 이후 봉을 하나도 쓰지 않아야 함.** 섞이면 기준선과 ML 성적이 둘 다 부풀려짐.

### 3-3. 결과 라벨

<!-- diagram: gosimple-ml-03-label.html -->

| 라벨 | 정의 |
|---|---|
| `ret_{1,5,20,60}` | N거래일 뒤 종가 수익률 |
| `ret20_next_open` | 다음 날 시가 진입 기준 20일 수익률 |
| `mfe_20` / `mae_20` | 20일 최대 상승률 / 최대 하락률 |
| `outcome_20` | +30% 먼저 = win, -15% 먼저 = loss, 둘 다 없음 = timeout |
| `label_complete` | 20거래일 봉이 다 있는지 |

- 진입가 = 사건일 종가(기존 채점과 같은 기준)
- 같은 날 +30% 와 -15% 를 둘 다 찍으면 loss. 일봉으로는 순서를 모름 → 보수적 처리

## 4. 기준선 비교

<!-- diagram: gosimple-ml-04-cohort.html -->

### 4-1. 코호트

| 코호트 | 정의 | 라벨 기준일 |
|---|---|---|
| 급등 전체 | 기준선, 클러스터 첫 사건만 | 사건일 |
| 급등 15% 이상 | DETECT 문턱 시험 | 사건일 |
| DETECT 통과 | 5개 조건 | 사건일 |
| CONFIRM 도달 | 60거래일 리플레이 | 사건일 |
| BUY_SIGNAL | 60거래일 리플레이 | 신호일 |

### 4-2. 지표

- n, 승률과 윌슨 95% 신뢰구간(Wilson interval)
- lift = 코호트 승률 − 같은 분기 기준선 승률
- `ret_20` 평균·중앙값, MFE·MAE 중앙값
- **분기별**로 끊어서 표시 → lift 부호가 분기마다 같은지가 핵심
- n < 30 셀 = "표본 부족" 배지

### 4-3. 대안 비교

| 방식 | 장점 | 단점 | 언제 쓰나 |
|---|---|---|---|
| 규칙 유지 | 설명 쉬움, 표본 적어도 동작 | 조건 간 상호작용 못 잡음 | 표본 수백 건 이하 |
| 규칙 + 통계 보정 | 기존 구조 유지, 근거 표시 쉬움 | 보정 범위 제한적 | 지금 단계 |
| ML 보조 점수 | 다변수 상호작용 학습 | 과적합, 근거 표시에 SHAP 필요 | 기준선을 뒤 기간에서 확실히 이길 때 |
| ML 단독 판정 | 자동화 최대 | 블랙박스, 국면 변화에 취약 | 쓰지 않음 |

## 5. 사용법 예시

### 5-1. 라벨 판정 (개념 코드)

```ts
// 사건일 다음 봉부터 20거래일 안에 +30% 와 -15% 중 먼저 닿은 쪽
function outcome20(bars: DailyBar[], i: number, up = 0.3, down = 0.15, days = 20) {
  const entry = bars[i].close;
  for (let k = i + 1; k <= i + days; k++) {
    const b = bars[k];
    if (!b) return null;                       // 봉 부족 → 라벨 미완성
    const hitUp = b.high >= entry * (1 + up);
    const hitDown = b.low <= entry * (1 - down);
    if (hitDown) return { outcome: 'loss', days: k - i };  // 같은 날 둘 다면 손실
    if (hitUp) return { outcome: 'win', days: k - i };
  }
  return { outcome: 'timeout', days };
}
```

### 5-2. 누수 방지 테스트 (개념 코드)

```ts
// 미래 봉을 잘라도 입력 지표가 같아야 함
it('사건일 이후 봉을 쓰지 않음', () => {
  const full = computeEventFeatures(bars, i, mcap, rank, cfg);
  const cut = computeEventFeatures(bars.slice(0, i + 1), i, mcap, rank, cfg);
  expect(cut).toEqual(full);
});
```

### 5-3. 2단계 - 분기 단위 시간순 검증

<!-- diagram: gosimple-ml-05-walkforward.html -->

- 앞 분기로 학습 → 다음 분기로 시험 → 한 분기 전진 반복
- 랜덤 분할 금지. 미래 데이터로 학습하는 셈이 됨

## 6. 실무에서 확인 - gosimple 환경 관점

- worker 는 `@gosimple/shared` 를 런타임 import 불가 → 순수 함수는 worker 에 바이트 동일 사본 + 동기화 테스트
- 전 종목 스윕 첫 실행은 Kiwoom 일봉 API 로 수십 분 → `candles` 캐시 재사용, 호출 간 완충 지연
- 과거 대금 순위 TR 없음 → 전 종목 일봉으로 날짜별 순위표 자체 생성
- 크론 = 평일 16:30 KST, `sgrade-scan`(15:40) 뒤. `guide.ts` 의 `GUIDE_DAY` 갱신 필요
- 완성된 사건의 입력 지표는 다시 쓰지 않음 → 시총 근사가 흔들려도 과거 사건 고정
- 마이그레이션 번호는 착수 시점 최신 번호 다음. 다른 브랜치가 번호 조정 대기 중

> 주의 : 생존 편향(survivorship bias). 유니버스가 현재 활성 종목이라 상장폐지된 급등주가 빠짐 → 절대 승률은 실제보다 높게 나옴. 코호트 간 비교(lift)는 덜 왜곡됨

> 주의 : 기준선 화면을 보고 임계값을 바꾼 뒤 같은 기간으로 다시 재면 안 됨. 그 순간 기준선이 과적합됨

## 7. 용어 정리

- **기준선(baseline)** : 비교 대상이 되는 단순한 성적. 여기서는 급등 전체의 승률
- **결과 라벨(label)** : 사건 뒤 실제로 일어난 일. 학습과 채점의 정답
- **미래 정보 누수(lookahead leakage)** : 판정 시점에 알 수 없던 정보가 입력에 섞이는 것
- **과적합(overfitting)** : 표본의 우연까지 외워서 새 데이터에서 성능이 떨어지는 것
- **lift** : 코호트 승률 − 기준선 승률
- **윌슨 신뢰구간(Wilson interval)** : 표본이 작거나 승률이 0·100% 근처일 때도 안정적인 비율 신뢰구간
- **MFE / MAE** : 보유 기간 중 최대 유리 이동폭 / 최대 불리 이동폭
- **시간순 검증(walk-forward)** : 과거로 학습하고 바로 다음 구간으로 시험하는 것을 반복하는 검증
- **생존 편향(survivorship bias)** : 사라진 표본이 빠져 결과가 좋게 보이는 편향
- **코호트(cohort)** : 같은 조건을 통과한 사건 묶음

## 8. 한 장 요약

| 항목 | 핵심 |
|---|---|
| 질문 | ML 이 지금 규칙보다 낫나 |
| 현재 | 규칙·캘리브레이션·통계 보정, 학습 모델 없음 |
| 막힌 이유 | 같은 잣대의 성적표 없음 |
| 1단계 | 급등 사건 전체(+10%) 에 입력 지표와 결과 라벨 |
| 라벨 | 20일 안에 +30% 먼저 = win, -15% 먼저 = loss |
| 기준선 | 코호트별 분기 승률, 신뢰구간, lift |
| 2단계 | 같은 표본으로 시간순 검증, 이기면 보조 점수 |
| 함정 | 미래 정보 누수, 생존 편향, 기준선 과적합 |

**ML 도입 여부는 의견이 아니라 뒤 기간 성적표로 정함.**
