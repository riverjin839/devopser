## Local AI Models on a Mac Ch15~18 - 문제 해결, RAG, Open WebUI, LangChain, 에이전트, 미세조정

> **목표** : 15~18장에서 에러 잡는 법과 챗봇 위에 얹는 확장 도구(RAG, Open WebUI, LangChain, 에이전트, 미세조정)를 정리하고, 폐쇄망 사내 환경에서 걸릴 지점을 짚음

- 기준 버전 : 책 예시 = Ollama 0.6.2, gemma3:4b, Open WebUI `main` 이미지 / 현재 확인 = Ollama 0.40.16, Open WebUI 0.13.3, langchain 1.5.0, langchain-ollama 1.1.0, langchain-core 1.8.0, chromadb 1.5.9, unsloth 2026.11.4 (2026-11 기준)

## 0. 챕터별 3줄 요약

### 15장. 흔한 에러와 트러블슈팅

- 모델 없음, 서버 꺼짐, 메모리 부족, 포트 중복, venv 꼬임, Python 버전, 이 6가지가 대부분임
- traceback 은 마지막 줄부터 읽고, 환경 → Ollama → 코드 → Streamlit 순으로 좁혀 감
- 구체 예외 처리와 logging 으로 사용자에겐 조치 문구, 개발자에겐 원인 기록을 남긴다

### 16장. RAG, Web UI, 미세조정으로 확장

- RAG 는 문서를 잘라 벡터 DB(ChromaDB)에 넣고 질문과 가까운 조각을 context 로 넣어 환각을 줄임
- Open WebUI 는 완성형 UI, LangChain 은 부품 조립, 에이전트는 도구를 스스로 골라 실행하는 루프임
- 바꾸는 순서는 system prompt → RAG → 미세조정이고, 미세조정은 Unsloth 학습 → GGUF → Ollama 등록으로 끝난다

### 17장. 2026년 오픈모델 혁명

- 2026-02 GLM-5, Qwen3-Coder-Next, MiniMax M2.5 가 주요 벤치에서 상용 모델과 대등했다는 주장임
- API 단가가 상용의 수십분의 일이라 호출이 많은 에이전트에서 오픈모델·로컬의 경제성이 커짐
- 단, 활성 파라미터가 작아도 다운로드는 수십 GB 라서 내 Mac 메모리로 직접 따져 봐야 한다

### 18장. 앞으로 어디로

- 이 책은 Level 1, 다음은 RAG 심화·LangGraph·배포(Level 2), 그다음 LoRA·멀티 에이전트·운영(Level 3)임
- 한 분야를 프로젝트 하나 끝날 때까지 깊게 파는 게 Level 2 의 핵심 조언임
- 도구 이름은 바뀌어도 모델 연결 → 응답 처리 → 화면 → 상태 → 에러 처리 원칙은 그대로다

## 2. 개념 정리

### 2-1. 문제 해결 (15장)

#### 2-1-1. 자주 나는 에러 6종

| 에러 | 원인 | 해결 |
|---|---|---|
| `model "x" not found` | 미다운로드·오타 | `ollama pull` 후 `ollama list`. 형식은 `이름:태그`, 태그 생략 시 `latest` |
| `Connection refused ... 11434` | Ollama 서버 꺼짐 | `ollama serve` → `curl localhost:11434` 에 "Ollama is running" 확인 |
| `requires more system memory` 또는 극단적 느림 | 모델이 RAM 보다 큼 | `ollama ps` → 작은 모델로, `ollama stop`. 총 RAM 의 절반 이하 모델 |
| `bind: address already in use` | Ollama 가 이미 떠 있음 | 대부분 기존 걸 그대로 쓰면 됨. 멈췄을 때만 `lsof -i :11434` → `kill` |
| `No module named 'streamlit'` | venv 미활성·다른 venv | `which python3`, `python3 -m streamlit run app.py` 로 인터프리터 고정 |
| `SyntaxError` / `cannot import name 'TypeAlias'` | Python 버전 낮음 | 3.12·3.13 으로 venv 재생성 |

- Homebrew 판과 데스크톱 앱 Ollama 를 동시에 쓰지 말 것 → 포트 충돌의 흔한 원인

#### 2-1-2. 좁혀 가는 순서

<!-- diagram: localai-ch15-debug.html -->

- traceback 은 **마지막 줄**(에러 타입·설명) → **내 코드 줄** → 위에서 아래 호출 흐름 순으로 읽음
- 체크리스트 4단계 = L1 환경 → L2 Ollama → L3 코드 → L4 Streamlit. 아래 층이 정상이어야 위 층을 의심할 의미가 있다
- 단계별 검증 스크립트 = import → `ollama.list()` 연결 → 단순 chat → 스트리밍 순으로 하나씩 확인
- `try/except` 는 구체 예외(`ConnectionError`, `ollama.ResponseError`) 먼저, 마지막에 `Exception`. 사용자에겐 traceback 대신 조치 문구
- logging = 파일·콘솔 핸들러. 개발 DEBUG, 운영 WARNING 이상
- LLM 에 디버깅을 물을 땐 traceback·명령·코드 조각만. 비밀번호·키·고객 데이터는 클라우드에 넣지 말 것. 답은 가설로만 취급

### 2-2. RAG 구현 (16.1)

#### 2-2-1. 벡터와 임베딩

- 임베딩(embedding) = 텍스트를 의미가 담긴 숫자 목록(벡터)으로 바꾼 것. "dog" 와 "puppy" 는 가까운 벡터
- 검색은 키워드가 아니라 벡터 거리로 함(유사도 검색, similarity search) → 단어가 달라도 의미가 같으면 찾음
- 비유 = 시험 전에 건네는 커닝페이퍼. 모델은 원래 똑똑하고, RAG 는 모르는 지식만 채워 줌

#### 2-2-2. 책 예제 흐름

<!-- diagram: localai-rag.html -->

- 1단계 예제 = 문장 8개를 하드코딩해 `collection.add()` → `collection.query(n_results=2)` → 결과를 context 로 `ollama.chat`
- 2단계 예제 = `./my_documents` 의 `.txt`·`.md` 를 읽어 500자씩 자름 → id 는 `파일명_chunkN`
- 프롬프트에 "context 에 정보가 부족하면 그렇다고 말하라" 를 넣음 → 환각을 크게 줄임
- 청킹(chunking) 이유 = 컨텍스트 창 한계, 그리고 문서 전체가 아니라 관련 부분만 보내기 위함

> 주의 : 책은 임베딩 모델을 따로 지정하지 않음. 이 경우 ChromaDB 가 기본 임베딩(all-MiniLM-L6-v2 ONNX)을 쓰고, 첫 사용 때 S3 에서 모델 파일을 받아 `~/.cache/chroma/onnx_models/` 에 둠 (chromadb 1.5.9 소스 기준). 폐쇄망이면 여기서 막힘

### 2-3. Open WebUI (16.2)

- ChatGPT 형 오픈소스 웹 UI. Ollama 에 붙으면 받아 둔 모델을 자동으로 인식함
- Docker 로 설치. 시스템 레벨 도구라 부담되면 건너뛰어도 된다는 입장 (책 진행에 필수 아님)
- `--add-host=host.docker.internal:host-gateway` = 컨테이너가 Mac 의 Ollama 에 접근, `-v open-webui:/app/backend/data` = 대화 영구 저장
- `http://localhost:3000` 첫 접속 때 로컬 관리자 계정 생성
- 기능 = 모델 드롭다운, 검색 가능한 기록, 문서 업로드(내장 RAG), 페르소나 저장, 사용자 관리, 내보내기(텍스트·JSON)
- Streamlit 앱 = 구조를 배우는 용도, Open WebUI = 완성품
- 완전 로컬을 유지하려면 임베딩·문서 처리도 로컬로 두고 외부 API·웹 도구를 꺼야 함

### 2-4. Modelfile 심화 (16.3)

- 13장 Modelfile 에 `TEMPLATE` 을 추가 → 대화를 모델이 학습한 형식으로 어떻게 감쌀지 정의
- `{{ .System }}`, `{{ .Prompt }}`, `{{ .Response }}` 로 끼워 넣음. 책 예제는 `.Messages` 로 기록을 순회하지 않음
- Llama 3 형식 토큰(`<|start_header_id|>`, `<|eot_id|>`)을 쓰고 `PARAMETER stop "<|eot_id|>"` 로 멈출 지점 지정
- 핵심 = Modelfile 하나로 같은 설정의 모델을 누구나 재현할 수 있다

> 주의 : TEMPLATE 은 모델 계열마다 형식이 다름. 틀리면 답이 끊기거나 특수 토큰이 그대로 출력됨. 기존 모델 템플릿은 `ollama show <모델> --template` 으로 보고 복사해서 고칠 것

### 2-5. LangChain (16.4)

- LLM 앱을 부품 조립식으로 만드는 프레임워크. Ollama 지원이 좋음
- `OllamaLLM(model="gemma3:4b")` 단독은 ollama 라이브러리 직접 호출과 큰 차이 없음 → 부품을 엮을 때 의미가 생김
- 체인(chain) = `prompt | llm | StrOutputParser()`. 유닉스 파이프처럼 앞 출력이 뒤 입력

| 부품 | 역할 |
|---|---|
| Prompts | 변수 넣는 프롬프트 템플릿 |
| Chains | 단계 연결 (prompt, llm, parser) |
| Memory | 대화 기록 자동 관리 |
| Tools | 검색·계산·DB 조회 함수 |
| Agents | 어떤 도구를 쓸지 스스로 판단 |
| Retrievers | 벡터 DB 연결 (RAG) |

- 책 코드(`ChatPromptTemplate`, `OllamaLLM`, `StrOutputParser`, `@tool`)는 langchain 1.5 / langchain-ollama 1.1 에서 그대로 import·조립됨을 확인함

### 2-6. 에이전트형 AI 패턴 (16.5)

#### 2-6-1. 판단하고 실행하는 루프

<!-- diagram: localai-ch16-agent.html -->

- 에이전트 = 행동하는 LLM. 도구 설명을 읽고 쓸지 말지, 어떤 도구에 어떤 입력을 줄지 스스로 정함
- 규칙 기반 선택이 아니라 언어 이해로 판단 → 맞는 도구가 없으면 자기 지식으로 바로 답함
- 여러 단계 작업은 이 평가·실행 사이클을 반복하면서 루프가 됨
- 책 코드는 `@tool` 로 `calculator`, `get_current_date` 두 개를 정의하고 이름·설명만 출력함 → 도구 층만 보여주고 루프는 구현하지 않음
- gemma3:4b 급은 에이전트 능력이 제한적, 7B 이상부터 쓸 만하다는 평가
- 활용 = 리서치 비서, 코드 비서, 데이터 분석, 개인 비서, 고객 지원(사람에게 이관 포함)

#### 2-6-2. OpenClaw 와 PicoClaw

<!-- diagram: localai-ch16-claw.html -->

| 항목 | OpenClaw | PicoClaw |
|---|---|---|
| 만든 곳 | Peter Steinberger (구 Clawdbot, Moltbot) | Sipeed |
| 형태 | gateway 와 protocol 분리, ClawHub 스킬 마켓 | Go 단일 바이너리, 의존성 없음 |
| 메신저 | WhatsApp, Telegram, Slack, Discord, Signal, iMessage, Teams | Telegram, Discord, QQ, DingTalk |
| 모델 | Ollama 로컬 포함 여러 백엔드 | 원격 (클라우드 API 또는 큰 머신의 Ollama) |
| 위험 | 파일 읽기·명령 실행 가능 → 고위험 셋업 | 런타임만 가벼움, 모델 메모리는 별도 |

- 핵심 패턴 = **에이전트 런타임과 모델 추론의 분리**. 가벼운 쪽이 메시지·도구를 맡고 무거운 추론은 서버가 맡음
- 프로젝트 이름·인기 수치는 빨리 바뀌니 현재 문서를 볼 것 (책도 같은 경고)

#### 2-6-3. 에이전트 비용

| 모델 | 입력 1M 토큰 | 출력 1M 토큰 | 구분 |
|---|---|---|---|
| Claude Opus 4.5/4.6 | $5.00 | $25.00 | 상용 |
| GPT-5.2 | $1.75 | $14.00 | 상용 |
| MiniMax M2.5 (API) | $0.30 | $1.20 | 오픈 |

- 표준가, 2026-09-08 기준 (캐시·배치·도구 요금 제외)
- 예 = 입력 1M + 출력 100K 면 Opus $7.50, MiniMax $0.42. 같은 토큰량 기준이지 같은 품질 보장은 아님
- 에이전트는 작업 하나에 수십~수백 번 호출함 → 상시 도는 에이전트에서는 비용이 결정적

> 주의 : 17장 표 17.1 은 같은 모델 출력 단가를 다르게 적음. 날짜가 명시된 16장 표를 기준으로 봄

### 2-7. 미세조정 (16.6)

#### 2-7-1. 언제 하나

| 방법 | 언제 | 예 | 비유 |
|---|---|---|---|
| System prompt | 성격·형식 변경 | "탐정처럼", "JSON 으로" | 지시 |
| RAG | 특정 지식 추가 | 사내 문서, 논문 | 참고서 |
| 미세조정(fine-tuning) | 근본 행동 변경 | 새 언어, 특수 도메인, 일관된 문체 | 재교육 |

- 대부분은 미세조정이 필요 없다는 입장. 위에서부터 차례로 시도

#### 2-7-2. Unsloth → Ollama 파이프라인

<!-- diagram: localai-ch16-finetune.html -->

- 데이터 = 입력·출력 쌍 JSONL. 쌍 하나가 "이런 요청엔 이런 답" 을 가르침
- 학습 도구 = Unsloth, Axolotl, Hugging Face. 책은 Unsloth 를 Colab 노트북에서 돌리는 경로를 권함
- export = `model.save_pretrained_gguf("my_model", tokenizer, quantization_method="q4_k_m")`
- GGUF 와 Modelfile 을 Mac 의 같은 폴더로 옮김 → `FROM` 경로가 실제 파일명과 같아야 함 → `ollama create` → `ollama run`
- Unsloth = 학습·변환 담당, Ollama = 서빙 담당. GGUF 가 둘을 잇는 공통 포맷이다
- Unsloth 효과(시간·GPU 메모리 절감)는 모델·하드웨어·설정에 따라 다름. 아키텍처·학습 방식·GGUF export 지원 여부를 먼저 확인

> 주의 : 학습 때 쓴 chat template 을 Modelfile 에서도 유지해야 함. 다르면 학습한 행동이 안 나옴

#### 2-7-3. 양자화 수준

| 포맷 | bit | 7B 파일 | 품질 손실 | 용도 |
|---|---|---|---|---|
| F16 | 16 | 약 14GB | 없음 | 최고 품질 |
| Q8_0 | 8 | 약 8GB | 거의 없음 | 준무손실 |
| Q4_K_M | 4 | 약 4.6GB | 작음 | 균형, Ollama 대부분 기본 |
| Q2_K | 2 | 약 2.7GB | 큼 | 실험용 |

- 파일 크기이지 필요 RAM 이 아님. 추론 땐 컨텍스트·런타임 메모리가 더 듦
- 7B 가중치 = 32bit 약 28GB, 16bit 약 14GB, 4bit 약 4~5GB. 내 모델 양자화는 `ollama show <모델>`

## 3. 비교 - 어떤 도구를 언제

### 3-1. UI·앱 계층

| 도구 | 기능 | 장점 | 단점 | 언제 쓰나 |
|---|---|---|---|---|
| Streamlit 직접 구현 | 내가 짠 챗봇 | 구조를 다 이해함, 자유도 | 기능을 다 직접 만들어야 함 | 학습, 특수 화면 |
| Open WebUI | 완성형 채팅 UI | 기록·RAG·사용자 관리 내장 | Docker 필요, 내부 구조 덜 보임 | 개인·팀용 실사용 |
| LangChain | 부품 조립 라이브러리 | RAG·도구·에이전트 재사용 | 추상화 층 추가, 버전 변화 큼 | 다단계 워크플로 |

### 3-2. 에이전트 배치 방식

| 방식 | 장점 | 단점 | 언제 쓰나 |
|---|---|---|---|
| 한 머신에 런타임과 모델 | 단순, 완전 로컬 | 큰 머신 필요 | 개인 실험 |

| 클라우드 API | 최고 성능, 무설정 | 호출 수만큼 비용, 데이터 외부 전송 | 성능 우선 단발 작업 |

## 5. 사용법 예시

### 5-1. RAG 를 Ollama 임베딩으로 (개념 코드)

```python
# 책 16.1 예제를 바꾼 개념 코드 - 임베딩도 Ollama 로 돌려 외부 다운로드 제거
import chromadb, ollama
from chromadb.utils.embedding_functions import OllamaEmbeddingFunction

ef = OllamaEmbeddingFunction(url="http://localhost:11434", model_name="bge-m3")  # 다국어 임베딩
client = chromadb.PersistentClient(path="./chroma")          # 재시작해도 유지
col = client.get_or_create_collection("my_docs", embedding_function=ef)

text = open("notes.md", encoding="utf-8").read()
chunks = [text[i:i + 500] for i in range(0, len(text), 500)]  # 책과 같은 500자 고정 청킹
col.upsert(documents=chunks, ids=[f"notes_{i}" for i in range(len(chunks))])

q = "Ollama 포트는?"
ctx = "\n---\n".join(col.query(query_texts=[q], n_results=3)["documents"][0])
prompt = f"아래 context 만 근거로 답하고, 없으면 모른다고 답함.\n\nContext:\n{ctx}\n\nQuestion: {q}"
print(ollama.chat(model="gemma3:4b", messages=[{"role": "user", "content": prompt}])["message"]["content"])
```

- 사전 준비 = `ollama pull bge-m3`. 책 예제의 `chromadb.Client()` 는 메모리 전용이라 실행이 끝나면 사라짐

### 5-2. LangChain 체인과 도구

```python
from langchain_ollama import OllamaLLM
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_core.tools import tool

prompt = ChatPromptTemplate.from_messages([
    ("system", "개념을 쉽게 설명하고 항상 비유를 하나 들어 줌"),
    ("human", "{concept} 을 입문자에게 설명해 줘"),
])
chain = prompt | OllamaLLM(model="gemma3:4b") | StrOutputParser()   # 파이프처럼 연결
print(chain.invoke({"concept": "벡터 DB"}))

@tool
def calculator(a: float, b: float) -> str:
    """두 수를 곱함. 곱셈이 필요할 때 사용."""      # 이 설명을 보고 LLM 이 도구를 고름
    return str(a * b)
```

- 실제 루프까지 돌리려면 도구 호출을 지원하는 채팅 모델(`ChatOllama` 의 `bind_tools`)과 tool calling 이 되는 모델이 필요함. 책 범위 밖

## 6. 실무에서 확인

### 6-1. 내 Mac (M1 Pro 16GB)

- RAG 실습 = gemma3:4b + bge-m3 임베딩 조합으로 메모리 여유 있음
- 에이전트 = 책 기준 7B 이상부터 쓸 만함 → 16GB 에선 8B Q4 가 상한이라 도구 호출 테스트는 llama3.1:8b 정도까지
- Qwen3-Coder-Next 는 q4 만 약 52GB → 이 Mac 에선 불가

### 6-2. 폐쇄망 함정

- **ChromaDB 기본 임베딩** → 첫 `add` 때 S3 에서 ONNX 모델을 받음. 폐쇄망에선 외부에서 받은 파일을 `~/.cache/chroma/onnx_models/all-MiniLM-L6-v2/` 에 미리 두거나, 5-1 처럼 Ollama 임베딩으로 바꿈
- **기본 임베딩은 영어 위주 모델** → 한국어 문서 검색 품질이 낮을 수 있음. 다국어 임베딩 모델로 바꾸고 직접 검색 결과를 비교해 볼 것
- **Open WebUI 임베딩** → 기본값이 HF 의 `sentence-transformers/all-MiniLM-L6-v2`. HF 프록시를 경유하거나 `OFFLINE_MODE=true` 로 두고 모델을 미리 반입. `RAG_EMBEDDING_ENGINE` 을 ollama 로 돌리는 것도 방법
- **Unsloth** → 베이스 모델·패키지를 HF·PyPI 에서 받음. Colab 대신 사내 B300 노드에서 돌리면 HF 프록시와 Nexus PyPI 프록시 둘 다 필요
- **Ollama 버전 차이** → 책 0.6.2, 현재 0.40.16. TEMPLATE·GGUF import 동작은 사내 버전으로 다시 확인

### 6-3. 멀티테넌트로 열 때

- Open WebUI 기본 DB 는 컨테이너 안 SQLite → 파드 재시작·다중 레플리카에 약함. `DATABASE_URL` 로 CNPG Postgres 연결
- 인증은 Keycloak OIDC (`OPENID_PROVIDER_URL`, `OAUTH_CLIENT_ID`). 첫 가입자가 관리자가 되므로 로그인 폼·가입 정책을 먼저 정함
- 문서 업로드(RAG) 데이터가 사용자 간에 섞이지 않게 지식베이스 공유 범위를 확인
- Ollama 는 인증이 없음 → Open WebUI 만 Ollama 에 붙도록 Cilium NetworkPolicy 로 제한
- OpenClaw 류 에이전트는 파일·명령 실행 권한이 핵심 → 사내 공용 배포는 보류. 실험한다면 전용 네임스페이스, 읽기 전용 볼륨, egress 차단부터

## 7. 용어 정리

- **traceback** : 에러가 난 호출 경로 출력. 마지막 줄부터 읽음
- **임베딩(embedding)** : 텍스트를 의미를 담은 벡터로 바꾼 것
- **유사도 검색(similarity search)** : 질문 벡터와 가까운 문서 벡터를 찾는 검색
- **청킹(chunking)** : 긴 문서를 검색·전달하기 좋게 조각내는 것
- **벡터 DB(vector database)** : 벡터 저장과 근접 검색에 최적화된 DB. 책은 ChromaDB
- **TEMPLATE** : Modelfile 에서 대화를 모델 학습 형식으로 감싸는 규칙
- **체인(chain)** : LangChain 에서 prompt, llm, parser 를 파이프로 이은 것
- **도구(tool)** : 에이전트가 호출할 수 있는 함수. 설명문이 선택 기준
- **에이전트(agent)** : 도구 사용을 스스로 판단하고 결과를 보며 반복하는 LLM
- **미세조정(fine-tuning)** : 사전학습 모델을 내 데이터로 추가 학습해 행동을 바꾸는 것
- **GGUF** : 양자화 모델 표준 파일 포맷. 학습 도구와 Ollama 를 잇는 형식
- **LoRA** : 가중치 전체 대신 작은 어댑터만 학습하는 효율적 미세조정 기법 (18장 로드맵에서 언급)
