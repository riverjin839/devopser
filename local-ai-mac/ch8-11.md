## Local AI Models on a Mac Ch8~11 - Streamlit·MLX Whisper 로 음성 챗봇 완성

> **목표** : 8~11장에서 웹 화면, 음성 인식, 두 개를 합친 음성 챗봇, 대화 기록 관리까지 만드는 과정을 장별로 정리함

- 출처 : Keiji Kamigusa, *Build Applications with Local AI Models on a Mac* 8~11장 (Part 2 후반)
- 기준 버전 : 책 예시 = streamlit 1.41.1, mlx_whisper 0.4.1, sounddevice 0.5.1, numpy 2.2.2, 기본 모델 `gemma3:1b`·`gemma3:4b` / 현재 확인 = streamlit 1.66.1, mlx-whisper 0.4.3 (2026-10 기준)

---

## 1. 개요

- 7장까지는 터미널에서 `ollama.chat()` 으로 대화하는 데까지 감. 8~11장은 그 위에 화면과 음성을 붙임
- 8장 Streamlit 으로 웹 화면 → 9장 MLX Whisper 로 음성 → 텍스트 → 10장 둘을 합쳐 음성 챗봇 → 11장 긴 대화에서 기록 관리
- 최종 구조는 아래와 같음. 음성과 텍스트가 한 함수로 모이고, Ollama 응답이 스트리밍으로 화면에 그려짐

<!-- diagram: localai-arch.html -->

**4개 장의 핵심은 "Streamlit 은 매번 처음부터 다시 실행된다" 하나다. 녹음 처리, 기록 유지, 확인 버튼이 전부 이 성질 때문에 생기는 설계임**

## 2. 개념 정리

### 2-1. Streamlit - Python 만으로 웹 화면 (8장)

#### 2-1-1. 무엇이고 어디에 맞나

- Python 스크립트를 웹앱으로 바꿔 줌. HTML·CSS·JS 는 Streamlit 이 대신 만듦
- 데이터 앱, 대시보드, 내부 도구, AI 챗봇 화면에 맞음
- 단, 계정·결제·대량 트래픽이 필요한 SNS·쇼핑몰은 대상이 아님

#### 2-1-2. 실행 모델 - 매번 처음부터

<!-- diagram: localai-ch8-rerun.html -->

- 사용자가 뭘 하든 스크립트 전체를 위에서 아래로 다시 실행함(rerun). 콜백·이벤트 핸들러가 없어서 코드가 단순함
- 위젯 함수는 화면에 그리면서 현재 값을 바로 돌려줌 → `name = st.text_input(...)` 한 줄로 그리기와 읽기가 끝남
- 단, 일반 변수는 rerun 마다 새로 만들어짐 → 남겨야 할 값은 `st.session_state` 에 둬야 한다

> 주의 : `st.button` 은 클릭된 그 rerun 에서만 True 임. 다음 rerun 에는 False 라서 버튼 아래 출력이 사라짐. 11장에서 이걸 session_state 로 풂

#### 2-1-3. 자주 쓰는 컴포넌트

| 분류 | 함수 |
|---|---|
| 텍스트 | `st.title`, `st.header`, `st.write`, `st.markdown`, `st.code` |
| 입력 | `st.text_input`, `st.text_area`, `st.selectbox`, `st.slider`, `st.checkbox`, `st.radio` |
| 액션 | `st.button` |
| 레이아웃 | `st.sidebar`, `st.columns`, `st.metric`, `st.divider` |
| 알림 | `st.success`, `st.info`, `st.warning`, `st.spinner` |
| 설정 | `st.set_page_config` (반드시 첫 Streamlit 호출) |

- 배치 관례 = 설정은 사이드바, 내용은 본문. 챗봇도 모델·temperature 는 사이드바, 대화는 본문에 둠

#### 2-1-4. 개발 루프

- 실행은 `python app.py` 가 아니라 `streamlit run app.py`
- 기본 포트 8501, 두 번째 앱부터 8502·8503 자동 배정. `--server.port` 로 지정, `--server.headless true` 로 브라우저 자동 실행 끔
- 파일 저장하면 브라우저 오른쪽 위에 Rerun / Always rerun 알림 → Always rerun 이면 저장할 때마다 반영됨
- VS Code 와 브라우저를 나란히 두고 저장 → 확인 반복

### 2-2. 음성 인식 - MLX Whisper (9장)

#### 2-2-1. Whisper 구조

- 음성 인식(ASR)은 억양·속도·잡음·연음 때문에 어려운 문제
- Whisper = OpenAI 가 2022년 공개, 68만 시간 다국어 음성으로 학습
- 인코더-디코더 트랜스포머 → 오디오를 멜 스펙트로그램으로 바꿔 인코더가 특징을 뽑고, 디코더가 언어·작업 토큰과 함께 한 단어씩 생성
- 영어는 사람 수준, 다른 언어는 그에 가까움. 완전 오프라인 동작

#### 2-2-2. 왜 MLX 인가

- 원본 Whisper 는 PyTorch 기반이라 Mac 에서는 CPU 로 돎
- MLX = Apple Silicon 전용 ML 프레임워크. CPU·GPU·Neural Engine 이 같은 메모리를 쓰는 통합 메모리 구조를 그대로 활용 → 복사 없음

| 모델 | PyTorch CPU | MLX | 배속 |
|---|---|---|---|
| tiny | 8초 | 2초 | 약 4배 |
| small | 28초 | 6초 | 약 5배 |
| medium | 75초 | 14초 | 약 5배 |
| large-v3 | 210초 | 38초 | 약 6배 |

- 측정 = Mac Mini M2 8GB, 60초 영어 음성. 보장값 아님

#### 2-2-3. 디지털 오디오 3요소

| 항목 | 값 | 이유 |
|---|---|---|
| 샘플링 주파수 | 16kHz | Whisper 학습 주파수. 처음부터 맞추면 리샘플 생략 |
| 채널 | mono (`channels=1`) | 음성 인식에 스테레오 불필요 |
| 자료형 | 녹음 float32, 저장 int16 | float32 는 -1.0~1.0, WAV 는 ×32767 해서 int16 |

- 5초 × 16,000 = 80,000 샘플. `sd.rec()` 결과는 (80000, 1) 모양 → `squeeze()` 로 1차원으로 폄

#### 2-2-4. 녹음에서 전사까지

<!-- diagram: localai-ch9-audio.html -->

- `mlx_whisper.transcribe(경로, path_or_hf_repo=...)` 결과는 dict. 책은 `text` 키만 씀 (`segments`, `language` 도 있음)
- HF 레포 이름을 주면 처음에 받아서 `~/.cache/huggingface/hub/` 에 캐시함. 로컬 폴더 경로도 됨
- 오디오 bytes 가 아니라 **파일 경로**를 넘김 → 그래서 10장에서도 임시 WAV 를 만듦
- 최종 모듈 `voice_input.py` = `record()`, `transcribe_array()`, `transcribe_file()`, `record_and_transcribe()` 4개 함수 + argparse CLI

#### 2-2-5. 모델 크기 고르기

| 모델 | 파라미터 | 다운로드 | RAM | 30초 처리 |
|---|---|---|---|---|
| tiny | 39M | 약 75MB | 약 200MB | 약 1초 |
| base | 74M | 약 145MB | 약 350MB | 약 2초 |
| small | 244M | 약 480MB | 약 800MB | 약 4초 |
| medium | 769M | 약 1.4GB | 약 2GB | 약 8초 |
| large-v3 | 1550M | 약 2.9GB | 약 4GB | 약 18초 |

- 레포 이름 규칙 = `mlx-community/whisper-{size}-mlx`
- 8GB 는 small (옆에 작은 Ollama 모델 여유), 16GB 이상은 medium 부터, 정확도 우선이면 large-v3
- 메모리가 주 제약. gemma3:4b 가 2~3GB 쓰고 그 위에 Whisper 가 얹힘

> 주의 : 본문은 small 다운로드를 약 244MB 로, 표는 약 480MB 로 적음. 244M 은 파라미터 수와 섞인 것으로 보임

## 3. 구조 - 음성 챗봇 완성 (10장)

### 3-1. 3단계로 붙여 가기

<!-- diagram: localai-ch10-stages.html -->

| 단계 | 하는 일 | 확인할 것 |
|---|---|---|
| Stage 1 | `st.audio_input` → 임시 WAV → Whisper → `st.success` | 말한 내용이 글자로 나오는가 |
| Stage 2 | `session_state.messages`, `st.chat_message`, `ollama.chat(stream=True)` | 대화가 쌓이고 답이 흘러나오는가 |
| Stage 3 | 사이드바, 텍스트 fallback, helper 함수, Clear | 최종본. 이전 코드를 통째로 교체 |

- 한 번에 다 짜지 않고 단계마다 돌려 봄(점진 개발). 문제가 나면 방금 붙인 부분만 보면 된다
- 녹음은 9장 `sounddevice` 대신 브라우저 쪽 `st.audio_input()` 을 씀 → 서버 마이크가 아니라 사용자 브라우저 마이크

### 3-2. voice_chat.py 구성 (파일 위에서 아래 순서)

| 위치 | 내용 |
|---|---|
| 설정 | `model_config.json` 경로, Whisper 모델 라벨 → HF 레포 매핑, Ollama 기본 설정 |
| 설정 로드 | `load_ollama_config()` → 파일 없음·JSON 깨짐·모델 없음이면 기본값으로 대체하고 경고 반환 |
| 페이지 | `st.set_page_config(page_title="Voice AI Chat", layout="wide")` |
| 사이드바 | LLM 선택, Whisper 선택, Temperature 0.0~2.0 (기본 0.7), Clear Conversation |
| 상태 초기화 | `messages` 가 없을 때만 빈 리스트 |
| helper | `transcribe_audio()`, `stream_response()`, `handle_user_message()` |
| 본문 | 기록 출력 → 음성 입력 → 텍스트 입력 (`st.chat_input`) |

- `stream_response()` 는 `st.empty()` 자리에 토큰을 이어 붙이며 끝에 `▌` 커서를 보여 주고, 다 받으면 커서를 지움
- 사이드바 선택은 라벨(사람용)과 실제 값(모델 태그·레포 경로)을 분리함 → `format_func` 로 라벨만 표시

### 3-3. 설계 포인트

- 임시 WAV : `st.audio_input()` 은 WAV bytes 를 담은 UploadedFile 을 줌. Whisper 는 경로를 받으니 `NamedTemporaryFile(delete=False)` 로 다리를 놓음
- `delete=False` 인 이유 : 안 그러면 `with` 블록이 끝날 때 Whisper 가 읽기도 전에 지워짐
- `try/finally` 로 `os.unlink` → 전사 중 에러가 나도 녹음 파일이 남지 않음. 프라이버시 측면에서도 중요함
- `.read()` 후 파일 포인터는 끝으로 감 → 다시 읽으려면 `.seek(0)`
- `.strip()` → Whisper 가 앞에 공백을 붙이는 경우 제거
- **입력 단일 진입점** : 음성·텍스트 둘 다 `handle_user_message()` 로 모음 → LLM 은 입력 출처를 모르고, 입력 방식 추가도 쉽다

> 주의 : 책은 `st.audio_input()` 이 Streamlit 1.31 에서 도입됐다고 적었지만, 직접 설치해 보면 1.39 는 `experimental_audio_input` 만 있고 `audio_input` 은 1.40 부터 있음. 1.40 이상 쓸 것

### 3-4. 실행 준비 파일

- `model_config.json` : 메뉴에 보일 Ollama 모델 목록(`name`, `label`, `notes`)과 `default_model`. 책 기본값은 `gemma3:1b`
- `setup_ollama.sh` : 서버가 없으면 띄우고, 준비될 때까지 기다리고, 기본 모델이 없으면 pull → 매 작업 시작마다 돌려도 안전
- 모델 추가 = `ollama pull` → `model_config.json` 의 `models` 에 추가 (`name` 은 태그와 정확히 같아야 함) → Streamlit 재시작

### 3-5. 지연 예산과 문제 해결

| 단계 | 시간 (M2 8GB, 5초 음성, whisper-small + gemma3:4b) |
|---|---|
| 업로드 | 약 0.1초 |
| Whisper 전사 | 약 1.5초 |
| Ollama 첫 토큰 | 약 0.5초 |
| 첫 단어까지 | 약 2.1초 |

- large-v3 로 바꾸면 전사만 4~5초
- 사람은 느린 생성은 참아도 말한 뒤 침묵은 못 참음 → 전사 중 `st.spinner("Transcribing...")`

| 증상 | 원인 | 해결 |
|---|---|---|
| No speech detected | 너무 짧거나 작음 | 2초 이상, 입력 볼륨 올림 |
| 전사 부정확 | small 모델 한계 | medium·large-v3 로 |
| Connection refused | Ollama 미실행 | `ollama serve` |
| 전사 중 멈춤 | 첫 모델 다운로드 | 다운로드 끝날 때까지 대기 |
| 브라우저 마이크 불가 | macOS 권한 | 개인정보 보호 → 마이크에서 브라우저 허용 |

- 테스트 체크리스트 중 핵심 = 음성으로 이름을 말하고 3턴 뒤 텍스트로 이름을 물어 맥락이 이어지는지 확인

## 4. 비교 - 대화 기록 관리 (11장)

### 4-1. 두 문제를 나눔

- 20~30턴 넘으면 반복·모순·지연 → 고장이 아니라 컨텍스트 창 한계
- LLM 은 stateless. `ollama.chat()` 호출마다 독립이라 앱이 기록을 매번 보내야 한다
- 그래서 두 문제로 나눔 → (1) 화면에 보일 기록 저장 (2) 모델에 보낼 양 조절
- `session_state` = 앱 메모리이지 모델 메모리가 아님

| 상황 | session_state |
|---|---|
| 버튼 클릭·입력 (rerun) | 유지 |
| 브라우저 새로고침 | 사라짐 |
| 탭 닫기 | 사라짐 |
| Streamlit 서버 재시작 | 사라짐 |
| 다른 탭·다른 사용자 | 서로 독립 |

### 4-2. 토큰 어림

- 글자 수 ÷ 4 ≈ 토큰. 8,192 토큰 ≈ 영어 약 6,000단어
- 응답 하나 200~500 토큰 → 20턴이면 5,000~10,000 토큰
- 컨텍스트 창에는 내 메시지, AI 답, 지금 생성 중인 답이 전부 들어감

| 모델 | 컨텍스트 |
|---|---|
| gemma2:2b | 약 8,192 |
| qwen2.5:3b | 약 32,768 |
| llama3.2:3b | 약 128,000 |

- 이 값은 모델이 감당 가능한 최대치. Ollama 가 실제 할당한 크기는 `ollama ps` 로 확인

### 4-3. 줄이는 방법 비교

<!-- diagram: localai-history.html -->

| 방법 | 동작 | 장점 | 단점 | 언제 쓰나 |
|---|---|---|---|---|
| 슬라이딩 윈도우 | 최근 N쌍만 전송 | 코드 두 줄, 예측 가능 | 앞 내용은 모델이 모름 | 대부분 경우 |
| 요약 삽입 | 오래된 대화를 요약해 앞에 넣음 | 긴 맥락 유지 | 요약 호출 비용, 손실 | 긴 상담·튜터 |
| RAG | 기록을 검색 DB 에 넣고 관련분만 회수 | 아주 긴 기록도 가능 | 구성 복잡 | 장기 기억 비서 |

- 책은 슬라이딩 윈도우만 구현함 (`chat_context.py`). 사이드바 `Max History` 1~50, 기본 10쌍
- 개수 기준이라 아주 긴 메시지가 섞이면 여전히 넘칠 수 있음. 보통 10~20턴 맥락이면 충분하다는 입장

> 주의 : 10장 `voice_chat.py` 는 자르지 않고 전체 기록을 보냄. 자르기는 11장 텍스트 챗봇에서만 시연함

### 4-4. 확인형 Clear 버튼

<!-- diagram: localai-ch11-confirm.html -->

- 버튼은 클릭한 rerun 에서만 True → 확인 단계를 두려면 "확인 중" 상태를 `session_state` 에 저장해야 함
- 흐름 = 클릭 → `confirm_clear = True` → `st.rerun()` → 다음 실행에서 경고와 Yes / Cancel 표시
- Yes = 기록 비우고 플래그 해제, Cancel = 플래그만 해제
- 삭제처럼 되돌릴 수 없는 동작 전반에 그대로 재사용 가능한 패턴

### 4-5. 그 밖의 패턴

- 대화 시작 시각을 한 번만 저장 → 사이드바에 경과 분 표시
- 이전 선택 모델을 저장해 두고 새 선택과 비교 → 바뀌면 사이드바에 알림
- 입력 하나가 처리되는 16단계 흐름 중 느린 곳은 토큰 생성 하나뿐 → 스트리밍 덕에 체감은 빠름

## 5. 사용법 예시

### 5-1. 설치

```bash
source .venv/bin/activate
pip install "streamlit>=1.40" mlx-whisper sounddevice numpy scipy
brew install ffmpeg                    # ffmpeg FileNotFoundError 예방
streamlit run voice_chat.py            # http://localhost:8501
```

### 5-2. 녹음 → 전사 최소 코드 (개념 코드)

```python
# voice_input.py 핵심만 줄인 개념 코드
import os, tempfile
import numpy as np, sounddevice as sd, mlx_whisper
from scipy.io import wavfile

SR = 16000                                          # Whisper 학습 주파수

def record(sec=5):
    audio = sd.rec(int(sec * SR), samplerate=SR, channels=1, dtype="float32")
    sd.wait()                                        # 녹음 끝날 때까지 대기
    return audio.squeeze()                           # (N, 1) → (N,)

def transcribe(audio, repo="mlx-community/whisper-small-mlx"):
    with tempfile.NamedTemporaryFile(suffix=".wav", delete=False) as f:
        path = f.name
    try:
        wavfile.write(path, SR, (audio * 32767).astype(np.int16))   # float32 → int16
        return mlx_whisper.transcribe(path, path_or_hf_repo=repo)["text"].strip()
    finally:
        os.unlink(path)                              # 녹음 파일 남기지 않음

if __name__ == "__main__":
    print(transcribe(record()))
```

import streamlit as st

st.session_state.setdefault("messages", [])
st.session_state.setdefault("confirm_clear", False)

    st.rerun()                                        # 바로 다시 실행해 경고 표시

if st.session_state.confirm_clear:
    st.sidebar.warning("대화 기록을 모두 지울까?")
    yes, no = st.sidebar.columns(2)
    if yes.button("Yes, clear it"):
        st.session_state.messages = []
        st.session_state.confirm_clear = False
        st.rerun()
    if no.button("Cancel"):
        st.session_state.confirm_clear = False
        st.rerun()

## 6. 실무에서 확인

### 6-1. 내 Mac (M1 Pro 16GB) 기준

- 책 기준대로면 16GB 는 Whisper medium 부터 가능 → `gemma3:4b` + whisper-medium 조합이 무난함
- 8B 모델로 올리면 Whisper 는 small 로 내려서 메모리 여유를 둠
- 마이크 권한이 두 군데 → 9장 스크립트는 터미널·VS Code 에, 10장 앱은 브라우저에 권한을 줘야 함

### 6-2. 코드 함정

- `st.audio_input` 은 rerun 후에도 마지막 녹음을 계속 돌려줌. 책 10장 코드에는 같은 녹음을 다시 처리하지 않게 막는 부분이 없음 → 텍스트를 입력하면 직전 음성이 한 번 더 들어갈 수 있다. 직접 돌려 보고, 겹치면 녹음 해시를 `session_state` 에 저장해 비교함
- 한국어 전사 → 책은 영어 위주라 언어 지정을 안 함. 자동 감지가 흔들리면 `mlx_whisper.transcribe(..., language="ko")` 로 고정해 볼 것 (책 범위 밖. mlx-whisper 0.4.3 소스에서 decode 옵션으로 받는 것까지 확인, 한국어 품질은 직접 테스트 필요)
- `voice_chat.py` 는 기록을 자르지 않음 → 11장 슬라이싱을 `stream_response()` 호출 직전에 붙여야 긴 음성 대화에서 안 느려짐

### 6-3. 사내로 가져갈 때

- 기록이 서버 메모리(`session_state`)에만 있음 → 파드 재시작이면 대화가 날아감. 남기려면 CNPG 같은 DB 에 사용자별로 저장해야 함
- Streamlit 은 브라우저와 WebSocket 으로 붙어 있음 → 레플리카를 여러 개 두면 인그레스에서 세션 고정(sticky session)이 필요
- 폐쇄망 설치 → pip 는 Nexus PyPI 프록시, Whisper 모델은 HF 프록시 경유하거나 모델 폴더를 반입해 로컬 경로로 지정
- 녹음 임시 파일을 바로 지우는 설계는 그대로 가져갈 것. 컨테이너에서는 `/tmp` 를 emptyDir(메모리)로 두면 디스크에도 안 남음

## 7. 용어 정리

- **rerun** : 사용자 조작마다 Streamlit 스크립트 전체를 다시 실행하는 동작
- **위젯(widget)** : 화면에 그리면서 현재 값을 돌려주는 Streamlit 입력 요소
- **session_state** : rerun 에도 살아남는 탭 단위 딕셔너리. 앱 메모리
- **음성 인식(ASR)** : 음성을 텍스트로 바꾸는 작업
- **멜 스펙트로그램(mel spectrogram)** : 소리를 사람 귀 감도에 맞춘 주파수 그림으로 바꾼 것. Whisper 입력
- **MLX** : Apple Silicon 전용 ML 프레임워크. 통합 메모리를 그대로 씀
- **샘플링 주파수(sample rate)** : 1초에 소리를 몇 번 재는지. Whisper 는 16kHz
- **UploadedFile** : `st.audio_input` 이 돌려주는 파일형 객체. WAV bytes 를 담음
- **점진 개발(incremental development)** : 기능을 단계별로 붙이며 매번 동작을 확인하는 방식
- **슬라이딩 윈도우(sliding window)** : 최근 N개 메시지만 모델에 보내는 기록 관리 방식
- **stateless** : 호출 사이에 기억이 없음. 맥락은 앱이 매번 다시 보냄

## 8. 한 장 요약

| 항목 | 핵심 |
|---|---|
| 8장 Streamlit | 조작마다 전체 rerun, 위젯은 그리면서 값 반환, 남길 값은 session_state |
| 9장 Whisper | 16kHz mono float32 녹음, int16 WAV 경로를 MLX Whisper 에 넘김 |
| 9장 모델 | 8GB 는 small, 16GB 이상은 medium 부터 |
| 10장 구조 | 브라우저 녹음, 임시 WAV, Whisper, handle_user_message, Ollama 스트리밍 |
| 10장 개발 | 3단계 점진 개발, 첫 단어까지 약 2.1초 |
| 11장 기록 | 화면엔 전체, 모델엔 최근 2N+1 개 |
| 11장 패턴 | confirm_clear 플래그로 2번 rerun 하는 확인형 버튼 |
| 함정 | audio_input 은 1.40 부터, 같은 녹음 재처리, 10장은 기록 미절단 |

**음성 챗봇은 Whisper 와 Ollama 를 이은 결과물이지만, 실제로 어려운 건 rerun 사이에 무엇을 남기고 무엇을 버릴지 정하는 일이다**
