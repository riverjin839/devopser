## 2. 개념 정리

### 2-1. 한 단계에서 일어나는 일

<!-- diagram: pylab-steploop.html -->

| 순서 | 동작 | 내용 |
|---|---|---|
| 1 | 단계 안내 | 목적과 실행할 명령을 보여줌 |
| 2 | 직접 입력 | 명령을 직접 침. Enter = 자동 입력, s = 건너뛰기, q = 종료 |
| 3 | 정답 비교 | 공백·따옴표 차이는 무시하고 비교. 틀리면 몇 번째 단어가 다른지 힌트, 2번 틀리면 정답 표시 |
| 4 | 명령 실행 | STEPS 에 정의된 조회 명령만 실행. 입력한 문자열은 비교에만 쓰고 실행 안 함 |
| 5 | 결과 파싱 | GB 환산, P+E 코어 검산, 배터리 건강도 같은 값 자동 계산 |
| 6 | 기록 | 확인 포인트 표시, 로그 저장. 시리얼이 들어간 출력은 기록 안 함 |

- 그룹이 끝나면 객관식 질문 1개로 복습함

### 2-2. 실습 단계 구성

| 그룹 | 단계 | 명령 |
|---|---|---|
| 1. OS 와 아키텍처 | OS 버전, 아키텍처, Rosetta 여부 | `sw_vers`, `uname -m`, `sysctl -n sysctl.proc_translated` |
| 2. 칩 | 칩 이름 | `sysctl -n machdep.cpu.brand_string` |
| 3. CPU 코어 | 전체, P 코어, E 코어 | `sysctl -n hw.ncpu`, `hw.perflevel0/1.physicalcpu` |
| 4. 메모리 | 총량, 여유율 | `sysctl -n hw.memsize`, `memory_pressure` |
| 5. 모델 정보 | JSON 구조 보기, 모델명, 식별자 | `system_profiler SPHardwareDataType -json` 와 `plutil` |
| 6. GPU | 이름, 코어 수 | `system_profiler SPDisplaysDataType -json` 와 `plutil` |
| 7. 스토리지 | 루트 볼륨, APFS 컨테이너 | `df -H /`, `diskutil info /` |
| 8. 배터리 | 사이클, 원시 용량 | `ioreg -r -c AppleSmartBattery` |

- 총 17단계. Rosetta, P/E 코어, GPU 코어, 배터리는 선택 항목 → 값이 없어도 계속 진행
- 단, 5단계의 JSON 전체 출력은 시리얼이 있어서 화면에만 보여주고 리포트엔 안 남김

### 2-3. 코드 구조

<!-- diagram: pylab-code.html -->

| 구성 | 역할 |
|---|---|
| `STEPS` | 단계 정의 리스트. 그룹, 명령, 목적, 확인 포인트, 파서 이름 |
| `QUIZ` | 그룹별 복습 질문 |

| `local_ai()` | 필요 메모리·속도·판정·추천 계산 |
| `report()` | 리포트 MD 작성 |

- 단계를 늘리려면 `STEPS` 에 dict 하나만 추가하면 됨 → 실행·로그·리포트에 자동 반영

## 3. 로컬 AI 계산 방식

<!-- diagram: pylab-aicalc.html -->

### 3-1. 계산식

| 항목 | 계산 | 근거 |
|---|---|---|
| GPU 가용 메모리 | 총 메모리 × 67% (64GB 이상은 75%) | macOS 기본 GPU 사용 한도 근사 |
| 필요 메모리 | 파라미터 × 양자화 바이트 + KV 캐시 + 1GB | 가중치 + 컨텍스트 비례 캐시 + 런타임 |
| 생성 속도 | 대역폭 × 0.6 ÷ 가중치 크기 | 토큰마다 가중치를 한 번 읽는 메모리 대역폭 병목 |
| 판정 | 가용의 90% 이하 = 여유, 90~100% = 빠듯, 초과 = 불가 | OS·앱 여유분 확보 |
| 일상용 추천 | Q4 · 여유 · 10 tok/s 이상 중 가장 큰 모델 | 대화가 끊기지 않는 최소 속도 |

- 양자화 바이트 : Q4 ≈ 0.61, Q8 ≈ 1.06, FP16 = 2.0 (파라미터당)
- KV 캐시 : 모델 크기별 토큰당 MB 근사값 × 컨텍스트 길이 (`--ctx` 로 변경)

### 3-2. 칩별 메모리 대역폭 표

| 세대 | 기본 | Pro | Max | Ultra |
|---|---|---|---|---|
| M1 | 68 | 200 | 400 | 800 |
| M2 | 100 | 200 | 400 | 800 |
| M3 | 100 | 150 | 300 / 400 | 819 |
| M4 | 120 | 273 | 410 / 546 | - |
| M5 | 153 | - | - | - |

- 단위 GB/s. Max 의 두 값은 GPU 코어 수(M3 30/40, M4 32/40)로 갈림
- 표에 없는 칩(M5 Pro·Max 등)은 실행 중에 대역폭을 물어봄. 모르면 GPU 코어 × 10 으로 추정하고 리포트에 "추정" 표시
- Intel 맥은 CPU 추론 기준(메모리 50%, 40 GB/s)으로 보수적으로 계산함

### 3-3. 계산 결과 예시

- 아래는 데모 모드 샘플(M4 Pro, 48GB, 컨텍스트 8K) 결과임. 실제 값은 내 맥에서 실행해서 확인

| 항목 | 값 |
|---|---|
| GPU 가용 메모리 | 약 32.2 GB |
| 대역폭 | 273 GB/s |
| 일상 대화용 추천 | 24B급 Q4 (필요 약 16.9GB, 약 11 tok/s) |
| 최대 적재 | 32B급 Q4 (필요 약 22.5GB, 약 8 tok/s) |
| 불가 | 32B급 Q8 이상, 70B급 전부 |

> 주의 : 속도는 근사치임. MoE 모델은 활성 파라미터만 읽어서 훨씬 빠르고, 프롬프트 처리(prefill)는 GPU 코어 수 영향이 더 큼

- 단계 정의 : dict 하나가 한 단계

```python
dict(group="3. CPU 코어", key="ncpu", title="전체 코어", cmd="sysctl -n hw.ncpu",
```

- 정답 비교 : 공백·따옴표를 정규화한 뒤 단어 단위로 처음 다른 위치를 찾음

```python
def norm(s):
    return " ".join(s.replace('"', "'").split())

if norm(s) == norm(cmd):
    print("정확함")
else:
    a, b = norm(s).split(), norm(cmd).split()
    i = next((k for k in range(min(len(a), len(b))) if a[k] != b[k]), min(len(a), len(b)))
    print("{}번째 단어부터 확인. 힌트 : '{}'".format(i + 1, b[i] if i < len(b) else "(끝)"))
```

- 판정 : 필요 메모리와 가용 메모리 비교, 속도는 대역폭 기준

```python
weights = params * bpp                                  # 가중치 GB
```

## 6. 실무에서 확인

### 6-1. 로컬 AI 장비 판단

- 사내 LLM 을 폐쇄망 클러스터 B300 노드에 올리기 전, 개인 맥에서 같은 모델 계열을 Q4 로 먼저 돌려 프롬프트·평가셋을 다듬는 용도로 씀
- 판정표의 "필요 메모리" 계산식은 GPU 노드 사이징에도 그대로 적용됨 → 파라미터 × 바이트 + KV 캐시(동시 요청 수 × 컨텍스트) + 런타임
- 단, 맥은 통합 메모리라 가용량 = 총량 × 67~75%, GPU 서버는 GPU 메모리 기준으로 따로 계산

### 6-2. 폐쇄망 반입

- 표준 라이브러리만 써서 pip 설치 없이 파일 하나로 반입 가능
- 모델 파일은 HF 프록시나 Nexus 경유로 받음 → 디스크 여유는 리포트의 "디스크 여유" 로 먼저 확인
- 단, 맥 arm64 에서 받은 MLX 변환 모델은 리눅스 GPU 노드에서 못 씀 → 서버용은 GGUF 나 원본 가중치로 따로 받음

### 6-3. 팀 장비 점검

- `--auto` 로 여러 대를 돌리면 같은 형식 리포트가 나옴 → 장비별 비교·교체 대상 선정에 씀
- macOS 27 부터 Intel 맥 지원 종료 → 리포트 아키텍처가 x86_64 인 장비 목록화

### 6-4. 확장 포인트

- `STEPS` 에 단계 추가 : 예) `sysctl vm.swapusage` (스왑), `pmset -g therm` (발열 제한)
- `MODELS` 에 사내 모델 크기 추가 → 판정표에 바로 반영
- 표에 없는 새 칩은 `BANDWIDTH` 에 공개 사양 값만 넣으면 됨

> 주의 : `run()` 은 `shell=True` 로 실행함. STEPS 에 명령을 추가할 땐 조회 명령만 넣고, 삭제·변경 명령은 넣지 않음

## 7. 용어 정리

- **통합 메모리(Unified Memory)** : CPU·GPU 가 같이 쓰는 메모리 풀, 로컬 AI 의 상한을 정함
- **메모리 대역폭(Memory Bandwidth)** : 초당 메모리에서 읽을 수 있는 양, 토큰 생성 속도를 정함
- **양자화(Quantization)** : 가중치를 적은 비트로 줄이는 것, Q4 는 FP16 의 약 1/3 크기
- **KV 캐시(KV Cache)** : 앞 토큰의 계산 결과를 저장하는 메모리, 컨텍스트 길이에 비례
- **컨텍스트 길이(Context Length)** : 한 번에 다루는 토큰 수, `--ctx` 로 계산 기준 변경
- **tok/s** : 초당 생성 토큰 수, 대화용은 10 이상이 무난함
- **prefill / decode** : 프롬프트 처리 단계 / 한 토큰씩 생성하는 단계
- **MoE(Mixture of Experts)** : 토큰마다 일부 전문가만 쓰는 구조, 전체 크기보다 빠름
- **GGUF** : llama.cpp·Ollama 가 쓰는 양자화 모델 파일 형식
- **MLX** : Apple Silicon 전용 머신러닝 프레임워크
- **plutil** : JSON·plist 에서 값을 뽑는 macOS 기본 명령
